# 存储配置系统用户指南

## 功能概述

存储配置系统用于灵活管理系统内各类文件的存放位置。通过该系统，管理员可以根据业务模块、资源类型将文件存储到不同的后端（如本地磁盘、S3 对象存储或 WebDAV），实现存储资源的按需分配与高效管理。

## 核心概念

- **存储后端 (Storage Backend)**: 实际存放文件的物理或云端位置。系统支持本地路径、Amazon S3 兼容存储以及 WebDAV 协议。
- **业务模块 (Module)**: 系统内不同的业务功能单元，如“花名册”、“宿舍管理”等。
- **资源类型 (Resource Type)**: 模块内更细分的文件类型，例如“头像”、“附件”、“导出文档”等。
- **存储规则 (Storage Rule)**: 定义了某个业务模块下的某种资源类型具体应该存放到哪个存储后端。

## 操作指南

### 1. 添加存储后端
在“系统设置 -> 存储配置”选项卡中，可以管理存储后端。
- **本地存储**: 需指定服务器上的绝对路径（请确保应用进程有读写权限）。
- **S3 存储**: 需提供 Endpoint、Region、Access Key、Secret Key 及 Bucket 名称。
- **WebDAV**: 需提供服务器 URL、用户名和密码。
- **默认后端**: 只能设置一个全局默认后端，当没有任何匹配规则时，系统将使用此后端。

### 2. 管理业务模块
在“系统设置 -> 模块配置”中定义系统支持的模块。
- 模块名称：方便识别的展示名。
- 模块编码：系统内部使用的唯一标识（不可随意修改）。
- 默认存储后端：为该模块指定一个默认的存储位置。

### 3. 创建存储规则
存储规则实现了文件存储的精细化控制。
- 进入“存储规则”设置。
- 选择目标**模块**。
- 输入**资源类型**（可选，留空则匹配该模块下的所有资源）。
- 选择对应的**存储后端**。

## 规则优先级与降级策略

当系统尝试存储一个文件时，会按照以下优先级确定最终的存储位置：

1.  **精确规则匹配**: 查找是否存在同时匹配 `模块编码` 和 `资源类型` 的规则。
2.  **模块默认配置**: 若无精确匹配，则使用该 `模块` 配置中指定的默认存储后端。
3.  **全局默认后端**: 若模块未指定默认后端，则使用被标记为“默认”的全局存储配置。

## 预定义模块列表

系统当前预定义的模块编码包括：
- `archives`: 人事花名册相关文件
- `dormitory`: 宿舍管理相关文件
- `provident`: 公积金业务文件
- `knowledge`: 知识库/文档管理
- `audit_logs`: 系统审计日志及备份

## 常见问题

**Q: 修改规则后，旧文件会自动迁移吗？**
A: 不会。规则只影响新上传的文件。旧文件仍保存在其上传时的存储位置。

**Q: 资源类型在哪里定义？**
A: 资源类型由具体业务功能决定，常见的如 `avatar`（头像）、`attachment`（附件）、`export`（导出文件）。如果不确定，可以为整个模块设置默认存储而不指定资源类型。

**Q: 如果存储后端失效了怎么办？**
A: 系统会报错提示无法写入。建议在修改配置前通过“测试连接”（如有）功能验证后端的可用性。
